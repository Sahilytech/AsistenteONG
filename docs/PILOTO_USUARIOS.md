# Piloto con usuarios reales

## Objetivo

Validar que una organización pueda completar un ciclo real de trabajo sin asistencia del desarrollador y detectar problemas de UX antes de una distribución amplia.

## Regla de seguridad

El primer piloto debe usar datos ficticios o previamente anonimizados. No usar expedientes reales hasta que la organización apruebe sus procedimientos de privacidad, permisos y backup.

## Perfil recomendado

- 1 coordinador/a.
- 1 o 2 operadores/as.
- 1 profesional que revise los informes.
- 1 persona responsable de tecnología/backup.

## Guion de prueba

Cada participante debe intentar, sin recibir instrucciones adicionales:

1. Configurar la institución.
2. Crear una persona.
3. Crear dos casos para la misma persona.
4. Consultar el historial.
5. Importar un PDF.
6. Encontrar evidencia relacionada con un caso.
7. Importar una planilla en modo revisión.
8. Confirmar una importación.
9. Crear una tarea/derivación.
10. Revisar y exportar un informe.
11. Bloquear y desbloquear la sesión.
12. Crear y restaurar un backup de prueba.

## Criterios de aceptación

- 90% de las tareas completadas sin ayuda.
- Ningún caso se duplica por una operación normal de alta.
- Ningún documento de vista previa se persiste sin confirmación.
- Ninguna coincidencia histórica/documental aparece presentada como decisión.
- El operador entiende cuándo se requiere revisión profesional.
- El backup de prueba puede restaurarse.
- El usuario puede identificar cómo obtener ayuda.

## Registro de problemas

Para cada problema guardar:

- pantalla;
- acción realizada;
- resultado esperado;
- resultado obtenido;
- gravedad: bloqueo / alta / media / baja;
- captura solo si no contiene información personal;
- pasos para reproducir.

## Cierre del piloto

El piloto se considera aprobado cuando los criterios anteriores se cumplen en dos sesiones consecutivas y no quedan bloqueos críticos abiertos.
